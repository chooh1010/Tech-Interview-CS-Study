<details>
<summary><b>꼬리 질문 3개 (펼치기)</b></summary>

- O(1)은 O(N^2) 보다 무조건적으로 빠른가요?

**내 답변**

``` 
알고리즘을 평가할떄 사용하는 지표로 시간 복잡도와 공간복잡도를 판단하는데 
그 중 시간 복잡도는 알고리즘의 수행시간을 평가하는 지표이고
공간복잡도는 알고리즘을 수행하기 위한 메모리의 크기(양)을 평가하는 지표입니다. 
```

**꼬리 질문 답변**

- Big-O, Big-Theta, Big-Omega 에 대해 설명해 주세요.
```
세 표기법 모두 함수의 점근적(asymptotic) 증가율을 표현하며, 차이는 "어떤 경계를 보장하느냐"이다.

- Big-O (O) — 상한(upper bound). 아무리 나빠도 이 정도 이상 걸리지 않는다는 보장. 보통 최악의 경우(worst case)를 나타낼 때 사용.
  예: 삽입 정렬은 O(n²) → 아무리 나빠도 n²을 넘지 않음.
- Big-Omega (Ω) — 하한(lower bound). 아무리 좋아도 최소 이 정도는 걸린다는 보장. 보통 최선의 경우(best case)를 나타낼 때 사용.
  예: 삽입 정렬은 이미 정렬된 배열이면 Ω(n).
- Big-Theta (Θ) — 상한과 하한이 같을 때(tight bound). O와 Ω가 동일한 함수로 수렴하는 경우, 정확히 이 정도 걸린다고 말할 수 있음.
  예: 병합 정렬은 최선/평균/최악 모두 n log n이므로 Θ(n log n).
```

- 다른 것을 사용하지 않고, Big-O를 사용하는 이유가 있을까요?
```
엔지니어링 관점에서는 "최악의 경우"가 가장 중요하기 때문이다. 시스템을 설계할 때는 평균적으로 얼마나 빠른지보다,
가장 나쁜 입력이 들어왔을 때도 시스템이 버틸 수 있는지가 더 중요하다 (SLA, 응답시간 보장 등).

Big-O는 안전한 상한을 제시하므로 성능을 보수적으로 예측하고 대비할 수 있다. Ω(최선의 경우)만 보고 설계하면
실제 최악의 상황에서 문제가 생길 수 있다.

또한 Θ는 항상 구할 수 있는 게 아니다. 최선과 최악의 경우가 다른 알고리즘(퀵 정렬 등)에서는 정확한 Θ를 정의하기
어려운 경우가 많아, 실용적으로 상한선인 O만 명시하는 경우가 많다.
```

- O(1)은 O(N^2) 보다 무조건적으로 빠른가요?
```
아니다. Big-O는 점근적(asymptotic) 개념으로, 입력 크기 n이 충분히 커질 때의 증가 추세를 나타내는 것이지
특정 입력값 하나에서의 절대적인 속도 비교가 아니다.

또한 Big-O 표기법은 상수 계수를 생략한다. 예를 들어 O(1)이 실제로는 1,000,000번의 연산이 걸리고,
O(n²)이 0.001 * n²번의 연산이 걸린다면, n이 작을 때는 O(n²) 쪽이 더 빠를 수 있다.

실제로 퀵 정렬(O(n log n))이 이론적으로 삽입 정렬(O(n²))보다 낫지만, n이 작을 때(보통 10~20 이하)는
삽입 정렬이 실제로 더 빠르다. 그래서 Timsort, IntroSort 같은 하이브리드 정렬은 작은 구간에서 삽입 정렬로 전환한다.

결론적으로 Big-O는 "n이 무한히 커질 때 누가 더 느리게 증가하는가"를 보장하는 것이지, "이 순간 이 입력에서
누가 더 빠른가"를 보장하지 않는다.
```
