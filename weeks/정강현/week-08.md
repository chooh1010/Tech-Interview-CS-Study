#### 1. DHCP가 무엇인지 설명해 주세요.

`★★☆` · `심화` · 원본 [네트워크 #8](../03-NETWORK.md)

<details>
<summary><b>꼬리 질문 5개 (펼치기)</b></summary>

- DHCP는 몇 계층 프로토콜인가요?
- DHCP는 어떻게 동작하나요?
- DHCP에서 UDP를 사용하는 이유가 무엇인가요?
- DHCP에서, IP 주소 말고 추가로 제공해주는 정보가 있나요?
- DHCP의 유효기간은 얼마나 긴가요?

</details>

**내 답변**

```
DHCP는 Dynamic Host Configuration Protocol의 약자로, 네트워크에 접속한 장치에 IP 주소와 네트워크 설정 정보를 자동으로 할당해주는 프로토콜입니다.

DHCP가 없다면 사용자가 직접 IP 주소, 서브넷 마스크, 게이트웨이, DNS 서버 등을 설정해야 합니다.

일반적으로 클라이언트가 네트워크에 접속하면 DHCP 서버와 통신해서 일정 기간 사용할 IP 주소를 임대받습니다.
```

**꼬리 답변**

```
1. OSI 기준으로 응용 계층 프로토콜입니다.
전송 계층에서는 UDP를 사용합니다.

2. 대표적으로 DORA 과정으로 설명합니다.
Discover
Offer
Request
Acknowledge

1. DHCP Discover
   클라이언트가 DHCP 서버를 찾습니다.
2. DHCP Offer
   DHCP 서버가 사용할 수 있는 IP 주소를 제안합니다.
3. DHCP Request
   클라이언트가 해당 IP를 사용하겠다고 요청합니다.
4. DHCP ACK
   서버가 IP 할당을 확정합니다.

3. DHCP를 처음 사용할 때 클라이언트는 아직 자신의 IP 주소도 제대로 가지고 있지 않습니다.

따라서 TCP처럼 먼저 연결을 수립하기보다 연결 설정 없이 Broadcast 기반으로 통신할 수 있는 UDP가 적합합니다.

일반적으로 DHCP 서버는 UDP 67번, 클라이언트는 UDP 68번 포트를 사용합니다.

4. 대표적으로:
- Subnet Mask
- Default Gateway
- DNS Server
- Lease Time
등을 함께 제공합니다.

즉 DHCP는 단순히 IP 하나만 주는 것이 아니라 네트워크에 접속하기 위해 필요한 설정들을 함께 제공합니다.

5. 고정된 시간이 있는 것은 아닙니다.

DHCP 서버가 Lease Time을 설정하며 네트워크 환경에 따라 몇 시간, 하루, 며칠 등 다양할 수 있습니다.

클라이언트는 임대 기간이 끝나기 전에 갱신을 요청합니다.

```

#### 2. IP 주소는 무엇이며, 어떤 기능을 하고 있나요?

`★★☆` · `필수` · 원본 [네트워크 #9](../03-NETWORK.md)

<details>
<summary><b>꼬리 질문 8개 (펼치기)</b></summary>

- IPv6는 IPv4의 주소 고갈 문제를 해결하기 위해 만들어졌지만, 아직도 수많은 기기가 IPv4를 사용하고 있습니다. 고갈 문제를 어떻게 해결할 수 있을까요?
- IPv4와 IPv6의 차이에 대해 설명해 주세요.
- 수많은 사람들이 유동 IP를 사용하고 있지만, 수많은 공유기에서는 고정 주소를 제공하는 기능이 이미 존재합니다. 어떻게 가능한 걸까요?
- IPv4를 사용하는 장비와 IPv6를 사용하는 같은 네트워크 내에서 통신이 가능한가요? 가능하다면 어떤 방법을 사용하나요?
- IP가 송신자와 수신자를 정확하게 전송되는 것을 보장해 주나요?
- IPv4에서 수행하는 Checksum과 TCP에서 수행하는 Checksum은 어떤 차이가 있나요?
- TTL(Hop Limit)이란 무엇인가요?
- IP 주소와 MAC 주소의 차이에 대해 설명해 주세요.

</details>

**내 답변**

```
IP 주소는 네트워크에서 장치를 논리적으로 식별하고, 패킷을 목적지까지 전달하기 위해 사용하는 주소입니다.

라우터는 패킷의 목적지 IP를 확인해서 어느 네트워크로 전달할지 결정합니다.

현재 대표적으로 IPv4와 IPv6가 있으며, IPv4는 32비트, IPv6는 128비트 주소를 사용합니다.

IP는 목적지까지 패킷을 전달하려고 노력하지만 TCP처럼 전달 성공이나 순서를 보장하지 않는 Best Effort 방식입니다.
```

**꼬리 답변**

```
1. 대표적으로 NAT를 사용합니다.

회사나 가정 내부에서는 여러 장치가 사설 IP를 사용하고, 외부 인터넷 통신 시 하나 또는 소수의 공인 IP를 공유할 수 있습니다.
PC       192.168.0.2
Phone    192.168.0.3
Laptop   192.168.0.4
             ↓ NAT
공인 IP  203.x.x.x

이 방식으로 IPv4 주소 소비를 크게 줄일 수 있습니다.

장기적으로는 IPv6 전환이 근본적인 해결 방법입니다.

2. 가장 큰 차이는 주소 크기입니다.
IPv4 → 32bit
IPv6 → 128bit

IPv6는 훨씬 큰 주소 공간을 제공하기 때문에 IPv4 주소 고갈 문제를 해결할 수 있습니다.

또한 IPv6에서는 헤더 구조가 단순화됐고 IPv4 헤더의 Header Checksum도 제거되었습니다.

3. DHCP 서버에서 특정 장치의 MAC 주소와 IP 주소를 연결해 예약할 수 있습니다.

이를 DHCP Reservation 또는 Static DHCP라고 합니다.

예를 들어:
AA:BB:CC:DD:EE:FF
→ 항상 192.168.0.10

처럼 설정할 수 있습니다.

4. 직접적인 주소 체계가 다르기 때문에 그대로는 어렵습니다.

대표적으로:
- Dual Stack
- Tunneling
- Translation
등의 방법을 사용할 수 있습니다.

Dual Stack은 장치가 IPv4와 IPv6를 둘 다 지원하도록 하는 방식입니다.

5. 아닙니다.

IP는 Best Effort 방식이기 때문에 패킷의 전달, 순서, 중복 제거 등을 보장하지 않습니다.

이러한 신뢰성이 필요하면 상위 계층의 TCP 등이 담당합니다.

6. IPv4의 Header Checksum은 IP Header 자체의 오류를 확인합니다.

반면 TCP Checksum은 TCP Header뿐 아니라 전송 데이터까지 포함해서 오류를 검출합니다.

또한 IPv6에서는 IP Header Checksum이 제거되었습니다.

7. TTL은 Time To Live로 패킷이 네트워크에서 무한히 순환하는 것을 방지하기 위한 값입니다.

라우터를 하나 지날 때마다 TTL이 1씩 감소하고,
TTL = 0

이 되면 패킷을 폐기합니다.

IPv6에서는 비슷한 개념을 Hop Limit이라고 합니다.

8. IP 주소는 네트워크 계층에서 사용하는 논리적 주소이고, MAC 주소는 데이터 링크 계층에서 사용하는 하드웨어 기반 주소입니다.

쉽게 말하면:
IP  → 멀리 있는 목적지까지 찾아가기 위한 주소
MAC → 현재 LAN에서 실제 장치를 찾기 위한 주소

입니다.
```

#### 3. www.github.com을 브라우저에 입력하고 엔터를 쳤을 때, 네트워크 상 어떤 일이 일어나는지 최대한 자세하게 설명해 주세요.

<details>
<summary><b>꼬리 질문 3개 (펼치기)</b></summary>

- DNS 쿼리를 통해 얻어진 IP는 어디를 가리키고 있나요?
- Web Server와 Web Application Server의 차이에 대해 설명해 주세요.
- URL, URI, URN은 어떤 차이가 있나요?

</details>

**내 답변**

```
브라우저에 www.github.com을 입력하면 먼저 해당 도메인의 IP 주소를 알아내기 위해 DNS 조회를 수행합니다.

먼저 브라우저 캐시, OS 캐시, hosts 파일 등을 확인하고 정보가 없다면 DNS Resolver에 질의합니다.

DNS를 통해 서버의 IP 주소를 얻으면 서버와 통신을 시작합니다.

같은 네트워크 밖에 있는 서버라면 Default Gateway를 통해 패킷을 전달하고, Ethernet 통신을 위해 ARP를 이용해 Gateway의 MAC 주소를 확인할 수 있습니다.

HTTP/1.1이나 HTTP/2를 사용한다면 TCP 3-Way Handshake를 통해 연결하고, HTTPS이므로 TLS Handshake를 수행해 서버 인증서 확인과 암호화에 사용할 키를 설정합니다.

이후 브라우저가 HTTP Request를 보냅니다.
GET /
Host: www.github.com

서버나 CDN, Load Balancer 등이 요청을 받아 적절한 서버로 전달하고 서버가 HTML 등의 HTTP Response를 반환합니다.

브라우저는 HTML을 파싱하면서 CSS, JavaScript, 이미지 같은 추가 리소스도 요청하고 최종적으로 화면을 렌더링합니다.
전체 흐름
URL 입력
 ↓
DNS 조회
 ↓
IP 주소 획득
 ↓
Gateway / ARP
 ↓
라우팅
 ↓
TCP 연결
 ↓
TLS Handshake
 ↓
HTTP Request
 ↓
Load Balancer / Web Server
 ↓
HTTP Response
 ↓
HTML 파싱
 ↓
CSS / JS / 이미지 추가 요청
 ↓
화면 Rendering

```

**꼬리 답변**

```
1.항상 최종 애플리케이션 서버 한 대를 직접 가리키는 것은 아닙니다.

서비스 구조에 따라:
CDN
Load Balancer
Reverse Proxy
Web Server

등의 앞단 장비 주소일 수 있습니다.
그 장비가 실제 요청을 내부 서버로 전달할 수 있습니다. 

2. Web Server는 주로 HTML, CSS, 이미지 등의 정적 콘텐츠 제공과 요청 전달을 담당합니다.

대표적으로 Nginx, Apache가 있습니다.

WAS는 애플리케이션 코드를 실행해서 동적 콘텐츠와 비즈니스 로직을 처리합니다.

예를 들어 Java 환경에서는 Tomcat 같은 서버가 사용될 수 있습니다.

Web Server
→ 정적 파일, Reverse Proxy

WAS
→ Java 코드 실행, DB 조회, 비즈니스 로직

3. URI는 인터넷의 리소스를 식별하는 가장 큰 개념입니다.

URL과 URN은 URI의 하위 개념으로 이해할 수 있습니다.

URL은 리소스의 위치를 표현합니다.
https://example.com/users/1

URN은 리소스를 이름으로 식별하는 방식입니다.

간단히: URI는 리소스를 식별하는 개념이고 URL은 그중 위치를 이용해 리소스를 표현하는 방식입니다.

```

#### 4. DNS에 대해 설명해 주세요.

<details>
<summary><b>꼬리 질문 7개 (펼치기)</b></summary>

- DNS는 몇 계층 프로토콜인가요?
- UDP와 TCP 중 어떤 것을 사용하나요?

</details>

**내 답변**

```
DNS는 Domain Name System의 약자로 사람이 이해하기 쉬운 도메인 이름을 IP 주소와 연결해주는 시스템입니다.

예를 들어:
www.github.com
        ↓ DNS
```
